# 1.1.4-rc.5 · 总库更新后的 AD 刷新

现场日志中，最初 ES8316 可以放置；随后新增 ES2310、删除并重新获取缓存、补齐 3D 时，工程库均已更新，但 AD 放置命令在约 1 ms 内返回，没有进入鼠标放置状态。工程总库仍保留此前的元件。用户确认完全重启 AD 后，同一个元件又能放置，符合 AD 仍在使用旧库内容的表现。

本版在共享核心中补上准备步骤：先在后台更新工程配套总库；返回界面线程，检查当前文档、工程和所选元件仍然一致；然后执行 AD 的 `IntegratedLibrary:RefreshInstalledLibraries`，参数 `AllLibraries=True`；最后交给原有 SDK 适配器执行放置。适配器再次核对工程和库文件时可复用已经准备好的文件。原有多版本适配 DLL 无需新增接口。

按工程库路径和内容校验值记录成功的刷新。相同内容再次放置不重复刷新；新增元件、重新获取、补齐 3D 导致工程库内容变化时再次刷新。首次在当前面板中放置也会刷新。刷新失败不会继续执行放置，也不会记作成功；切换目标文档或元件则停止当前请求。

仍使用同一对工程 `LibrarySearch.SchLib` / `LibrarySearch.PcbLib`，不按元件新增工程库文件。删除下载缓存不删除工程使用过的元件。

## 验证

SDK 形状夹具验证刷新在界面线程执行、先准备库再调用放置、重复放置复用、内容变化重新刷新、失败重试和目标变化保护。既有总库增删、旧工程保留、rc.3 数据恢复及独立 PcbLib 格式检查继续执行。夹具中的 SDK DLL 仅在独立测试目录构造，不随安装包分发。

刷新进程由安装机 `IntegratedLibrary.INS` 注册；API 范围参考 [Altium Integrated Library API](https://www.altium.com/documentation/altium-dxp-developer/integrated-library-api)。代码检查与 SDK 夹具不能证明各 AD 实机的缓存均已刷新，仍需用户验证“先放置 → 新增另一个元件 → 删除缓存再获取 → 再放置”，确认期间不必重启。

安装时先保存全部文件并退出 AD，完整解压运行 Install.cmd。AD 实机操作由用户进行，本次没有自动修改真实 AD 安装、工程或下载目录。
