# 1.1.4-rc.4 · 总库放置闪退修复

2026-11-08 的现场日志显示：rc.3 完成 23 对元件的总库更新，进入 C365735 / ES8316 的放置命令后未返回。Windows 记录 X2.EXE 异常 0x0eedfade；转储的异常线程栈中出现 IntegratedLibrary / Advpcb 地址，与封装库读取失败相符。

确认的文件错误在 PcbLib 的 SectionKeys：每条映射应为两个带 32 位块长度的 Pascal 字符串；rc.3 遗漏了第一个块长度。原读入器同样按错误布局解析，导致本地读回检查通过，AD 原生加载器却按错误长度继续读取。修复同时改正写入器和读入器，并加入独立的字节合同测试。独立核对依据为 [AltiumSharp 的 ReadSectionKeys / ReadPascalString 实现](https://github.com/issus/AltiumSharp/blob/master/src/OriginalCircuit.Altium/Serialization/Readers/PcbLibReader.cs)。

升级后，面板会根据新总库签名自动重建已有下载；放置前也会重建旧工程的受管总库。读入器仅在恢复 rc.3 数据时接受旧布局，所有新输出统一使用正确布局。原始编号缓存和索引不更改，不需要重新下载元件，工程之前使用的元件保留。

请先保存工程并完全退出 AD，再完整解压运行 Install.cmd。重开面板，等待总库更新，再放置元件。不要继续用 rc.3 的导出库。若面板提示总库文件被外部编辑或锁定，保留文件并导出反馈，不要手工删除工程元件。

验证包含：现场 23 对元件的只读副本恢复；同名元件、字体、STEP、删除和回滚回归；独立 Python OLE 字节检查；多运行时核心及安装检查。代码和文件格式检查不能替代 AD 实机放置验收，本次不宣称解决其他来源的模型偏移或历史闪退。
